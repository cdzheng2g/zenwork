# 检测超时与 TCP 资源上限

## 检测超时

- RKNN 阻塞执行显式传入 `rknn_run_extend.timeout_ms`，默认 30000 毫秒。
- 整轮检测由主线程的单次定时器监测，默认 60000 毫秒，包括线程池等待时间。
- 可通过环境变量 `HANS_RKNN_RUN_TIMEOUT_MS` 和 `HANS_INSPECTION_TIMEOUT_MS` 配置，接受 1–600000 毫秒；无效值使用默认值。生产配置应根据整轮方案的最大正常耗时确定，并为多模型、多文字区域留出余量。
- 整轮超时后立即锁定故障、停止自动触发并将 Modbus Ready 置为 false。原任务仍在运行时保持 Busy，所有触发入口拒绝新任务。
- 原任务稍后返回 OK 时，总结果改为 ERROR；如果方案已失效，继续遵守原有的旧结果丢弃规则。单算子测试保持不发送生产结果的规则。
- SDK 返回超时错误时，抛出专用异常，当前轮停止执行后续算子。超时会话禁止再次推理或重新加载。
- 故障状态在任务返回、切换方案、恢复预览后均不自动清除；需要后台任务结束后重启应用恢复。

### 边界

当前版本已增加独立推理进程：应用定时器发出取消，固定执行线程结束本地 IPC 等待并终止子进程。关闭时使用相同取消路径。子进程的模型加载、运行、输出获取卡住不会要求主线程无限等待；没有强杀应用线程或清除故障后并发启动新推理。终止等待最多 500 ms，内核中不可终止的子进程仍可能需要设备级恢复。

SDK 超时参数是否被目标板实际运行库执行，仍需板端故障验证。主线程被其他同步操作阻塞时，定时器通知可能延迟；检测执行线程自身也有截止时间。详见 [九项改进](reliability-improvements.md)。

## TCP 结果通道

- 最多 16 个已接入客户端。
- 每客户端 Qt 待发送缓冲最多 1 MiB；提交前检查当前积压与新消息之和，超限立即断开该客户端。
- 单条 JSON 行超过 1 MiB 时拒绝发送并报告错误。
- 检查发送提交返回值，提交不完整时断开，避免继续发送残缺 JSON 行。
- 该端点是只发布结果的 JSON 行协议：客户端发送应用数据时立即断开，接收缓冲同时限制为 4096 字节。已有心跳或命令需求应通过另行定义的协议处理。
- 停止服务和拒绝慢客户端使用 abort，不等待积压数据排空。未交付数据会丢弃并通过错误信号报告相关拒绝；本次未增加业务确认或补发协议。
- 遍历客户端快照，避免同步断开信号修改正在遍历的列表。

## 验证

原有检测服务与 RKNN 替身测试增加超时场景；新增 `test_inspection_timeout` 验证运行器的超时异常传播与后续算子停止，新增 `test_tcp_limits` 使用本机连接验证协议、连接上限、接收拒绝和发送积压上限。

硬件运行库故障、NPU 恢复及实际生产耗时需要在目标板另行验收。
